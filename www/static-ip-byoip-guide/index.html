Cloudflare Static IPs & BYOIP

By default, proxied hostnames resolve to shared Cloudflare anycast IPs that can change at any time. Static IPs give you dedicated Cloudflare addresses that stay fixed. BYOIP (Bring Your Own IP) lets Cloudflare announce your own prefix from every data center. This guide explains how both work, how a client connection travels through them, and every step to implement them.

0. Why customize the IPs Cloudflare uses

ALLOWLISTS

Fixed, known addresses

Partners, corporate firewalls, and mobile apps that pin IPs need addresses that do not change without notice.

APEX / A RECORDS

No CNAME needed

Partial (CNAME) setups and SaaS custom hostnames can point an apex A record at a static IP when the DNS provider cannot flatten CNAMEs.

OWNERSHIP

Keep your reputation

BYOIP keeps traffic on addresses you own: same IP reputation, geolocation registration, and contracts, but with Cloudflare's network in front.

Availability: Static IPs and BYOIP are Enterprise add-ons arranged through your account team. Free, Pro, and Business zones always use the shared anycast pool, and Cloudflare does not rotate those IPs on request.

2. How a client connection works

The same path applies to Static IPs and BYOIP. The only difference is who owns the address the client connects to.

  1. DNS lookup

    The client resolves shop.example.com. The record is proxied (orange cloud), so Cloudflare never returns the origin IP. Because the zone is a member of an address map, it answers with 203.0.113.10 instead of a shared anycast IP.

  2. Routing to the nearest data center

    Cloudflare announces 203.0.113.0/24 with BGP from all its locations (anycast). The client's ISP picks the shortest path, so the TCP SYN or QUIC packet lands in the closest Cloudflare data center. Static IPs are part of Cloudflare's own announced ranges, so this step is identical.

  3. Service binding

    The data center looks up which product owns the destination IP: CDN (HTTP proxy), Spectrum (TCP/UDP proxy), or Magic Transit (L3). Unspecified IPs use the prefix's default binding.

  4. TLS and hostname

    For CDN, the TLS ClientHello carries SNI, which selects the zone and edge certificate. The IP does not decide which site is served. Clients without SNI get the address map's default_sni.

  5. Security and performance

    DDoS mitigation, WAF, bot rules, Workers, and cache run exactly as they do for shared IPs. A cache hit is returned immediately.

  6. Origin connection

    On a miss, Cloudflare connects to the origin in the DNS record (198.51.100.7). The source IP is a shared Cloudflare egress IP, or your dedicated CDN egress IPs if you have them (section 6). Address maps never change this leg.

  7. Response

    The origin answers Cloudflare, and Cloudflare answers the client from 203.0.113.10 over the same connection.

3. BYOIP building blocks

4. Static IPs: step by step

  1. Order the add-on

    Ask your account team for Static IPs on the Enterprise contract. Decide how many IPs and whether you need IPv4, IPv6, or both.

  2. Receive the IPs

    Cloudflare allocates the addresses to your account. You can see them in the dashboard under Address space → Leased IPs. Cloudflare also creates an address map containing them. You cannot create a second map with the same static IPs.

  3. Choose the zones

    Go to IP addresses → Address maps, open the Cloudflare-created map, and select Review. Add the zones that should answer with the static IPs, or add the whole account. A zone membership overrides an account membership.

    curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/addressing/address_maps/$MAP_ID/zones/$ZONE_ID" \
  --request PUT \
  --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"

  4. Enable the map

    Make sure the map is enabled. DNS answers change only when the map is enabled and the zone is a member, with no expected downtime.

  5. Verify DNS

    dig +short shop.example.com A
192.0.2.10
192.0.2.11

  6. Publish the IPs

    Give the addresses to partners or firewalls, or point an apex A record at them (partial zones, SaaS custom hostnames).

  7. Optional: Spectrum and non-SNI

    For Spectrum apps, set "edge_ips": {"type": "static", "ips": ["192.0.2.10"]}. For clients without SNI, set default_sni on the map (API only).

Token permission: address map changes need Address Maps Write.

5. BYOIP: step by step

  1. Check the prerequisites

    • Prefix registered at an RIR (ARIN, RIPE, APNIC, LACNIC, AFRINIC).
    • Size: IPv4 /24 or larger; IPv6 between /48 and /32.
    • IRR route/route6 object that exactly matches the prefix, with origin: AS13335.
    • RPKI ROA for the prefix and AS13335, checked in Cloudflare's RPKI portal and a second validator.
    • Contract includes BYOIP. Announcing under your own ASN needs the account team.
    route:   203.0.113.0/24
descr:   Example Corp served by Cloudflare
origin:  AS13335
mnt-by:  MAINT-EXAMPLE
source:  RIPE

  2. Add the prefix

    curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/addressing/prefixes" \
  --request POST \
  --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  --json '{"cidr":"203.0.113.0/24","asn":13335,"delegate_loa_creation":true}'

    Save id and ownership_validation_token. With delegate_loa_creation, Cloudflare generates the Letter of Agency for you. The prefix starts with approved: "P" (pending).

  3. Prove ownership

    Use one of the two methods:

    # Option A: IRR route object remarks/descr
cf-validation: <OWNERSHIP_VALIDATION_TOKEN>

# Option B: reverse DNS zone 113.0.203.in-addr.arpa
cf-validation.113.0.203.in-addr.arpa. IN TXT "<OWNERSHIP_VALIDATION_TOKEN>"

    Then trigger validation and poll until IRR, RPKI, and ownership pass and approved becomes "V":

    curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/addressing/prefixes/$PREFIX_ID/validate" \
  --request POST --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"

curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/addressing/prefixes/$PREFIX_ID" \
  --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"

  4. Create service bindings

    List services (GET /accounts/$ACCOUNT_ID/addressing/services), then bind the whole prefix to the default service. Optionally bind smaller CIDRs to another service:

    curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/addressing/prefixes/$PREFIX_ID/bindings" \
  --request POST --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  --json '{"cidr":"203.0.113.0/24","service_id":"<CDN_SERVICE_ID>"}'

curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/addressing/prefixes/$PREFIX_ID/bindings" \
  --request POST --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  --json '{"cidr":"203.0.113.64/27","service_id":"<SPECTRUM_SERVICE_ID>"}'

    Each binding takes 4–6 hours (provisioning → active). Cloudflare creates the BGP prefix in a withdrawn state; allow at least 5 hours before advertising. Group contiguous IPs into one CIDR instead of one binding per IP.

  5. Advertise the prefix

    curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/addressing/prefixes/$PREFIX_ID/bgp/prefixes" \
  --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"

curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/addressing/prefixes/$PREFIX_ID/bgp/prefixes/$BGP_PREFIX_ID" \
  --request PATCH --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  --json '{"on_demand":{"advertised":true}}'

    Propagation takes minutes. If the prefix is currently announced by your own network or ISP, plan the cutover with them so traffic moves cleanly to Cloudflare.

  6. Create the address map (CDN)

    curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/addressing/address_maps" \
  --request POST --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  --json '{
    "description": "shop on BYOIP",
    "enabled": true,
    "ips": ["203.0.113.10", "203.0.113.11"],
    "memberships": [{ "identifier": "<ZONE_ID>", "kind": "zone" }]
  }'

    Spectrum apps use edge_ips type static with BYOIP addresses instead. Not needed for Magic Transit or Gateway.

  7. Verify, then move production

    Check DNS, BGP, and HTTP (section 7) before announcing the change to users.

Rules to remember: one BYOIP prefix can be used for CDN ingress or CDN egress, not both. Magic Transit can only be the default binding of a whole prefix. Delegations let another account use part of the prefix, but bindings stay in the parent account.

6. Egress IPs: Cloudflare to your origin

Static IPs and BYOIP change the address clients connect to. Traffic from Cloudflare to your origin comes from different addresses.

ProductDirectionWhat it gives you
Dedicated CDN Egress IPs (Smart Shield Advanced, formerly Aegis)Cloudflare → origin (CDN, WAF, Spectrum)A few IPs reserved for your account, so the origin firewall can allow only them. About 40,000 concurrent connections per IP per origin IP:port. Can use a BYOIP prefix (egress-only).
Gateway dedicated egress IPsYour users → Internet (Zero Trust)Static source IPs for SaaS allowlists, selected by egress policies. At least two IPs in two cities. Cloudflare-leased or BYOIP.
Shared Cloudflare rangesCloudflare → origin (default)Published at cloudflare.com/ips. Allowlist all of them, or use Authenticated Origin Pulls or Cloudflare Tunnel instead.

CheckCommand / placeExpected

Served by Cloudflarecurl -sI https://shop.example.com --resolve shop.example.com:443:203.0.113.10server: cloudflare and a cf-ray header

  • Validation fails: the IRR object does not exactly match the prefix, the origin is not AS13335, the ROA max-length is too short, or the token is missing.
  • DNS still returns shared IPs: the map is disabled, the zone is not a member, the record is DNS-only (grey cloud), or a resolver is caching the old answer (check the TTL).
  • Cannot add IPs to an address map: the BGP prefix is still withdrawn or the CDN binding is not active.
  • TLS errors on the new IP: the client sends no SNI and no default_sni is set, or the hostname has no edge certificate.
  • Connection resets after a binding change: bindings take 4–6 hours and reset traffic on IPs already in use. Change bindings only on unused IPs.
