→

Security → Web assets → Client-side resources

The monitoring header Cloudflare adds looks like this:

content-security-policy-report-only: script-src 'unsafe-inline' 'unsafe-eval'; connect-src 'none'; report-uri https://csp-reporting.cloudflare.com/cdn-cgi/script_monitor/report?...
  • script-src without 'self' or hosts — every external script (first- or third-party) triggers a report, which is how the script inventory is built. Inline code is allowed, so it is not listed.
  • connect-src 'none' — every fetch, XHR, sendBeacon, and WebSocket triggers a report, including same-origin ones. Images, styles, and iframes are outside this policy.
  • Report-only — nothing is blocked. Blocking comes only from your content security allow rules (content-security-policy).
  • Cookies are not reported by the browser. Cloudflare reads them from HTTP traffic: Set-Cookie from the origin (First-party) and Cookie sent by the browser (Unknown if not set by the origin).

4. Cookies

Four cookies come from Apache (.htaccess in this folder) as Set-Cookie headers, so Page Shield classifies them as First-party and records their attributes. Two are created in the browser with document.cookie. Cloudflare sees those only when the browser sends them back in the Cookie header on the next request, and classifies them as Unknown. Reload once to send them.

Origin cookies not detected. Deploy www/page-shield/page-shield-origin/.htaccess (needs AllowOverride All and mod_headers). If the page was served from cache, purge it.
NameSet byPage Shield typeAttributesLifetimeIn this browser

  • ps_origin_session is HttpOnly. JavaScript (and a skimmer) cannot read it, but Page Shield still lists it because it saw the Set-Cookie header.
  • ps_origin_weak has no Secure, HttpOnly, or SameSite. Filter by Secure = No or HTTP only = No to find cookies like this.
  • ps_origin_tracker uses Domain=pimenta.fun, so it is also sent to shop. and api., and SameSite=None allows cross-site sending.
  • For Unknown cookies, only Domain and Path are shown, derived from the host and page, because Cloudflare never saw their attributes.
  • You may also see Cloudflare cookies such as __cf_bm or cf_clearance when Bot Management or challenges are active.

7. Verify in the dashboard

  1. Generate reports

    Reload this page 5–10 times, since the monitoring header is sampled. Section 5 tells you when a view was sampled.

  2. Open the inventory

    Cloudflare dashboard → zone pimenta.fun → Security → Web assets → Client-side resources. Use View all scripts / connections to include Infrequent entries.

  3. Filter to this page

    Add the filter Seen on page = www.pimenta.fun/page-shield/page-shield-origin/. For cookies, filter Type or names starting with ps_.

  4. Check headers from a terminal

    curl -sI https://www.pimenta.fun/page-shield/page-shield-origin/ | grep -iE 'set-cookie|content-security|x-served-by|cf-ray'

    Run it a few times: set-cookie and x-served-by appear every time; the monitoring header appears only on sampled responses.
