Cloudflare Dynamic DNS

Keep the lab hostnames (www, shop, api, aop) pointed at the current public IP of a GCP VM — created if missing, updated only when the IP changes, and re-run automatically on a schedule.

GCP VMreads its external IP
(metadata server)
→cf-ddns.sh
daily via cron
Cloudflare APIlook up each A record
→create / update
only if changed
DNS recordswww · shop · api · aop
(proxied)
How it works: the script reads the VM's external IP from the GCP metadata server (falling back to ipify.org / ifconfig.me), looks up each A record via the Cloudflare API, creates it if missing, updates it only if the IP changed, and logs every run to /var/log/cf-ddns.log. Keep the records proxied (PROXIED="true") so Cloudflare features — WAF, mTLS, Authenticated Origin Pulls — still apply.

0. Prerequisites

  • A GCP VM (or any Linux host) running your origin, on the zone pimenta.fun.
  • The two files from the repo's ddns/ folder: cf-ddns.sh and cf-ddns.env.example.
  • sudo access on the VM; curl and jq (installed in step 2).

The apply sequence

Run steps 1–4 in order to apply dynamic DNS. Steps 5–6 are optional hardening / alternatives.

  1. Create a scoped Cloudflare API token Dashboard

    Cloudflare dashboard → My Profile → API Tokens → Create Token → Create Custom Token:

    • Permissions: Zone → DNS → Edit
    • Zone Resources: Include → Specific zone → pimenta.fun
    • Create and copy the token (it is shown only once).
    Use a scoped token, not the Global API Key.

  2. Install on the VM CLI

    From inside the ddns/ folder on the VM, install dependencies, the script, and the config:

    # Dependencies
sudo apt update && sudo apt install -y curl jq

# Install the update script
sudo install -m 0755 cf-ddns.sh /usr/local/bin/cf-ddns.sh

# Config directory + file
sudo mkdir -p /etc/cf-ddns
sudo cp cf-ddns.env.example /etc/cf-ddns/cf-ddns.env
sudo nano /etc/cf-ddns/cf-ddns.env         # paste token, confirm RECORDS
sudo chmod 600 /etc/cf-ddns/cf-ddns.env    # protect the token

# Log file
sudo touch /var/log/cf-ddns.log

    Fill in the config file — paste the token from step 1 and confirm the record list:

    /etc/cf-ddns/cf-ddns.env
    # /etc/cf-ddns/cf-ddns.env  — readable by root only (chmod 600)

# Cloudflare API token: Zone > DNS > Edit, scoped to pimenta.fun
CF_API_TOKEN="paste-your-scoped-token-here"

# The zone (root domain) that holds the records
CF_ZONE_NAME="pimenta.fun"

# Optional: hard-code the Zone ID to skip a lookup call (Overview page).
# Leave blank to auto-resolve by name.
CF_ZONE_ID=""

# Space-separated A records to keep in sync
RECORDS="www.pimenta.fun shop.pimenta.fun api.pimenta.fun aop.pimenta.fun"

TTL="120"        # seconds (use 1 for "Auto")
PROXIED="true"   # "true" = proxied (orange), "false" = DNS only (grey)
LOG_FILE="/var/log/cf-ddns.log"

  3. Test it manually CLI

    Run the sync once and check the log:

    # Run the sync once, then read the log
sudo /usr/local/bin/cf-ddns.sh
sudo tail -n 20 /var/log/cf-ddns.log

    Expected output:

    2026-06-03 09:00:01 Current public IP: 34.12.34.56
2026-06-03 09:00:01 Zone pimenta.fun -> a1b2c3...
2026-06-03 09:00:02 UPDATED www.pimenta.fun: 1.2.3.4 -> 34.12.34.56
2026-06-03 09:00:02 UPDATED shop.pimenta.fun: 1.2.3.4 -> 34.12.34.56
2026-06-03 09:00:02 Done.

    Confirm the records resolve (proxied records return Cloudflare IPs, which is correct):

    dig +short www.pimenta.fun @1.1.1.1
dig +short shop.pimenta.fun @1.1.1.1

  4. Schedule the daily cron job CLI

    Install a root cron entry that runs every day at 03:00:

    # Recommended: /etc/cron.d entry (note the required user column)
sudo tee /etc/cron.d/cf-ddns >/dev/null <<'EOF'
# m h dom mon dow user command
0 3 * * * root /usr/local/bin/cf-ddns.sh >> /var/log/cf-ddns.log 2>&1
EOF
sudo chmod 644 /etc/cron.d/cf-ddns

    Or add it to root's crontab instead:

    # Alternative: root's crontab
sudo crontab -e
# add this line:
0 3 * * * /usr/local/bin/cf-ddns.sh >> /var/log/cf-ddns.log 2>&1
    Schedule cheatsheet: 0 3 * * * = daily at 03:00 · */5 * * * * = every 5 min (ephemeral IPs) · @reboot = also run on every boot.

That's it. Dynamic DNS is now applied — the records self-heal to the VM's current IP every day. The sections below are optional.

5. Reserve a static IP in GCP optional

A daily cron is fine when the VM has a static external IP or rarely reboots. If the IP is ephemeral, either run the cron more often (every 5 minutes) or — the better fix — reserve a static IP so the record only ever needs to be set once. The daily cron then remains a safe self-healing backstop.

# Promote the VM's current ephemeral IP to a reserved static IP
gcloud compute addresses create pimenta-ip \
  --addresses "$(curl -s -H 'Metadata-Flavor: Google' \
    http://metadata.google.internal/computeMetadata/v1/instance/network-interfaces/0/access-configs/0/external-ip)" \
  --region YOUR_REGION

6. systemd timer instead of cron alternative

If you prefer systemd over cron, install a oneshot service plus a daily timer:

sudo tee /etc/systemd/system/cf-ddns.service >/dev/null <<'EOF'
[Unit]
Description=Cloudflare DDNS update
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/cf-ddns.sh
EOF

sudo tee /etc/systemd/system/cf-ddns.timer >/dev/null <<'EOF'
[Unit]
Description=Run Cloudflare DDNS daily

[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true

[Install]
WantedBy=timers.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now cf-ddns.timer
systemctl list-timers cf-ddns.timer

7. Troubleshooting

SymptomFix
zone not found / token lacks accessToken must include Zone:DNS:Edit for pimenta.fun.
could not determine public IPCheck egress; the metadata server only works on GCP. Test curl https://api.ipify.org.
Record proxied / unproxied wrongSet PROXIED="true" or "false" in the env file.
No log output from cronConfirm cron is running: systemctl status cron.
Want to see the exact requestRun sudo bash -x /usr/local/bin/cf-ddns.sh for a verbose trace.
