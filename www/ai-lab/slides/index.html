Why this matters

Everyone wants AI. Four worries stall it.

Cost & reliability

Token spend is opaque; providers rate-limit and go down.

Safety

Prompt injection, PII leakage, and unsafe content are real risks.

Integration

Getting AI to safely touch real systems and data is hard.

Ops

Nobody wants to run GPUs or glue five vendors together.

Cloudflare answers all four on one platform.

The portfolio

Four building blocks

Workers AI

Run models. Serverless GPU inference, one API, global network.

AI Gateway

Control & observe. Caching, rate limits, retries, cost & latency analytics, logs.

Protect. Scan prompts for injection, PII, unsafe topics.

Connect agents. Expose your tools/data to any MCP client.

Run models

Workers AI

  • Open models (Llama, Mistral, embeddings, image, speech) on Cloudflare GPUs
  • One binding, one call — no infrastructure to manage
  • Runs close to users on the global network
const out = await env.AI.run(
  "@cf/meta/llama-3.1-8b-instruct-fast",
  { messages: [{ role: "user", content: "Write a tagline." }] }
);
Control & observe

AI Gateway

  • Proxy in front of any provider (Workers AI, OpenAI, Anthropic…)
  • Caching cuts cost & latency · rate limits · retries/fallbacks
  • Dashboards: requests, tokens, cost, cached %, latency · full logs
await env.AI.run(model, input,
  { gateway: { id: "pimenta-lab" } });   // one-line change
Protect · Enterprise

Firewall for AI

  • WAF detection (AI Security for Apps) scans LLM prompts
  • Signals: prompt injection, PII, unsafe topics, token count
  • Act with normal WAF/rate-limit rules — no app changes
(cf.llm.prompt.injection_score gt 50)
  or (cf.llm.prompt.pii_detected)
  or (cf.llm.prompt.unsafe_topic_detected)   →  Block
Connect agents

MCP on Workers

  • Model Context Protocol = a standard way for AI agents to call your tools
  • Deploy a remote MCP server on Workers with createMcpHandler
  • Back tools with real data: D1 (SQL), KV (key/value), Workers AI
  • Works with Claude, Cloudflare AI Playground, MCP Inspector
How it fits

Lab architecture

MCP client (Claude / AI Playground / Inspector)
      │  Streamable HTTP (JSON-RPC)
      ▼
  ai-mcp Worker  (/mcp)
   ├─ create_note / list_notes / get_note / delete_note ──►  D1
   ├─ kv_put / kv_get ───────────────────────────────────►  KV
   └─ ask_ai ──►  AI Gateway  ──►  Workers AI (LLM)
      ▲
  Firewall for AI  — scans prompts (injection / PII / unsafe)

How it's built

Bindings do the wiring

// wrangler.jsonc
{
  "ai": { "binding": "AI" },
  "d1_databases": [{ "binding": "DB", "database_name": "pimenta-ai-mcp" }],
  "kv_namespaces": [{ "binding": "KV" }]
}
