How the Interactive Challenge works

The full request lifecycle when a challenge is applied to this path.

  1. Request hits Cloudflare.You request a protected path with no valid clearance token yet.
  2. Cloudflare returns a challenge page.Instead of your content, the edge responds with an interstitial and the header cf-mitigated: challenge.
  3. You interact.The Interactive Challenge asks for a human action (a click / checkbox); the widget runs its checks in the background.
  4. Cloudflare verifies & issues clearance.On success the edge sets a cf_clearance cookie (HttpOnly, Secure) scoped to the zone.
  5. Your request is replayed to the origin.This page is served, and every later request carries cf_clearance so you are not challenged again until it expires.
Interactive vs Managed: Cloudflare now recommends the Managed Challenge action, which automatically picks the lightest challenge (often no interaction). The Interactive Challenge action always shows an interaction. Both set the same cf_clearance clearance cookie on success.

Why cf_clearance is not listed: the clearance cookie is set HttpOnly and Secure, so it is deliberately not readable from JavaScript. Its presence is proven by the fact this page loaded without a challenge — you can see it in your browser dev-tools under Application → Cookies.

How to apply it to this path

Cloudflare dashboard: Security → WAF → Custom rules → Create rule.

Match this path and set the action to Interactive Challenge (or Managed Challenge):

# Expression
(http.host eq "www.pimenta.fun" and starts_with(http.request.uri.path, "/challenges/interactive/"))

# Action: Interactive Challenge      (or: Managed Challenge)
  • Tune how long a pass lasts under Security → Settings → Challenge Passage (default 30 min).
  • Verified bots and requests with valid clearance skip the challenge automatically.
  • Reload after clearing the cf_clearance cookie to see the challenge again.
