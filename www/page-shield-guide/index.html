Page Shield (Client-side security) — discovery & implementation

How Page Shield protects your visitors from client-side supply-chain attacks (Magecart), every option it offers, and every way to verify it is working — with a live interactive lab to test each feature.

0. What it is

Page Shield is Cloudflare's client-side security product (renamed Client-side security in the dashboard, Security → Client-side security). Modern sites load third-party JavaScript for analytics, ads, chat, and payments. If one of those suppliers is compromised, the attacker can skim data straight out of your visitors' browsers — credit cards, credentials, PII — without ever touching your origin. That is a client-side supply-chain attack, and the most famous variant is Magecart (payment-card skimming).

Because your server never sees this traffic, server-side security (WAF, API Shield, mTLS) cannot see it either. Page Shield closes that gap: it watches what runs in the visitor's browser and can block anything you have not allowed.

Availability: the base product is on every plan — including Free. Richer monitoring (connections, cookies, alerts) and ML detection + blocking policies are tiered; see the feature table in section 2.

1. How it works

Browserloads scripts, makes connections, sets cookies
→edge injects CSP headers
Cloudflarecollects violation reports, builds resource inventory
→analysis: known-good + ML classifiers
Alert & blockemail alerts, dashboard, CSP enforcement
  1. Data collection. Cloudflare injects Content-Security-Policy-Report-Only / Content-Security-Policy headers (and report ingestion endpoints) into HTML responses. The browser then tells Cloudflare exactly which scripts loaded, which remote hosts scripts talked to, and which cookies were touched.
  2. Inventory. Reports are aggregated into the zone's inventory: scripts (with hash, first/last seen, page attribution), outbound connections, and cookies.
  3. Detection. New or changed resources trigger alerts. With the Advanced add-on, each detected script is downloaded and run through ML classifiers (Magecart, cryptomining, malware, JS integrity) against a 1–99 risk scale.
  4. Action. Beyond visibility, you can deploy CSP policies in log mode (observe) and, when ready, enforce mode — the browser itself refuses to execute non-allowlisted code.

3. Implementation steps

  1. Dashboard → your zone → Security → Client-side security → Enable. Monitoring starts within minutes as real browsers hit pages.
  2. Let it baseline for a few days. Review the inventory: every script, connection, and cookie that is known-good on your site.
  3. Set up alerts (Notifications): New Script Detected, New Domain Detected; on Advanced also Malicious Script, Malicious Connection, Script Code Change.
  4. (Advanced) Create a CSP policy in Log mode: allow what the inventory says should be there. Cloudflare injects Content-Security-Policy-Report-Only; scripts still execute, browsers report violations.
  5. Review the violation reports for a week or two. Tuning the allowlist here is where all false positives are caught.
  6. Flip the policy to Enforce. The edge now emits Content-Security-Policy and browsers block everything not in the allowlist before it runs.
  7. Keep alerts on permanently. Any new third-party, marketing tag change, or compromise fires an alert within minutes.

4. CSP policies (log & enforce)

ModeHeader injectedBehavior
LogContent-Security-Policy-Report-OnlyEverything runs; violations are only reported to Cloudflare. Zero user impact.
EnforceContent-Security-PolicyBrowser blocks non-allowlisted scripts/connections before execution.
Content-Security-Policy:
  script-src 'self' cdnjs.cloudflare.com cdn.jsdelivr.net js.stripe.com;
  connect-src 'self' api.example.com www.google-analytics.com;
  report-uri https://csp-reporting.cloudflare.com/cdn-cgi/script_monitor/report?p=<policy_id>

Cloudflare is the reverse proxy: it adds these headers to HTML responses on the way out, the browser enforces them, and violation reports flow back to Cloudflare's reporting endpoint for the dashboard.

5. Ways to check & verify it works

  1. Dashboard inventory. Security → Client-side security: verify your known scripts/connections/cookies appear with sane first-seen dates. The interactive lab's live inventory panel mirrors what you should see.
  2. DevTools → Network → document headers. Reload a page and confirm the CSP headers are present (report-only in log mode, enforce header in enforce mode). The lab's Probe CSP headers button does this from the page itself.
  3. Console violations. With an enforce policy, a non-allowlisted script shows a browser console error (Refused to load the script ... violates Content Security Policy) and fails in the Network tab.
  4. New-script alert test. Deploy a page that loads a brand-new third-party URL (the lab injects cdn.evil-tracker.invalid) and confirm the New Script Detected alert fires and the URL appears in the inventory.
  5. GraphQL Analytics API. Query Page Shield detection data programmatically (same dataset that powers the dashboard) for automation or a custom view.
  6. Logpush (Advanced). Stream detection events to a SIEM and verify they arrive (4 jobs: detections for scripts, connections, cookies, code changes).
  7. Malicious-score spot check (Advanced). Set a low threshold, load a known-suspicious script in a test page, confirm the ML score + Malicious Script alert.

6. Best practices

  • Monitor → log → enforce. Never enforce on day one; use the log period to build a trustworthy allowlist.
  • Treat every new domain alert on checkout-like pages as urgent. Most Magecart incidents start with one unknown URL or hash change.
  • Page attribution: if a resource only ever appears on /checkout, that's your riskiest signal — watch it.
  • Minimize the blast radius: fewer third-party scripts = smaller attack surface. Page Shield tells you what is actually used.
  • Pair with Subresource Integrity (SRI) on scripts you control; Page Shield covers the ones you don't.
  • Try every flow in the interactive lab: live CSP probe, real inventory, Magecart walkthrough.
